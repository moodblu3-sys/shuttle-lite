# .envのアクセストークンでBoxに接続する

社用Macの `.env` にトークンを設定する。トークンをチャットやGitHubへ送らない。
コードは `feat/review-workspace` ブランチのトークン対応版を取得する。

## 設定

既存の `.env` に、次の2項目を設定する。
`.env` がない場合だけ `.env.example` をコピーし、既存設定を上書きしない。

```dotenv
BOX_MODE=real
BOX_ACCESS_TOKEN=ここにアクセストークン本体を設定
```

- `Bearer ` は付けない。トークンの前後の空白は除去される。
- `BOX_ACCESS_TOKEN` が設定されていれば、CCGの3項目
  (`BOX_CLIENT_ID` / `BOX_CLIENT_SECRET` / `BOX_ENTERPRISE_ID`) は不要。
- 両方が設定されている場合はアクセストークンを優先する。
  無効・期限切れでも別のユーザーへ切り替わらないよう、CCGへ自動で切り替えない。
- トークンが空の場合は従来のCCG方式を使う。
- プロキシが必要な環境では既存のプロキシ設定を維持する。トークン方式でも同じ経路を使う。

Developer Tokenは、Box Developer Consoleの対象アプリのConfigurationから生成する。
発行したユーザーに紐づき、有効期限は60分。プログラムから更新できない。
開発・デモで使用し、長時間の運用ではCCGなどの認証方式を使う。
[Box公式: Developer tokens](https://developer.box.com/guides/authentication/tokens/developer-tokens/)

## 接続だけを確認する

```sh
npm run check:box
```

`users/me` の読み取りだけを行い、接続に使用しているユーザーを表示する。
フォルダー作成、アップロード、移動、削除、Box AIの実行は行わない。
`BOX_MODE=fake` の場合は実Boxへ接続したように見えないよう、確認を終了する。

この成功は認証とユーザー情報取得の確認であり、ファイル操作・Box AI・
メタデータ操作の権限がすべて揃っていることを意味しない。

## 移行を始める前に

既存のデモ環境を使う場合は、`.env` の `BOX_ROOT_FOLDER_ID` などがその環境を
指していることと、トークンのユーザーがアクセスできることを確認する。
初回は、前述の接続確認とは別に、専用領域のフォルダーとメタデータテンプレートを準備する。
既存の `npm run bootstrap:box` はこれらを作成・確認するためのコマンドであり、読み取り専用ではない。

準備が済んだら `npm run demo` でWebとWorkerを起動し、画面から移行を作成する。

## 期限切れ・差し替え

401応答は `BOX_AUTH` として扱い、トークンの更新とアプリの再起動を案内する。
401だけでは期限切れとその他の無効化を区別できないため、期限切れと断定しない。

1. アプリを停止する。
2. 新しく発行したトークンを `.env` の `BOX_ACCESS_TOKEN` に設定する。
3. `npm run check:box` で接続を確認する。
4. `npm run demo` でWebとWorkerを再起動する。
5. 失敗扱いになったファイルがあれば、進捗画面で再実行する。

実行中のプロセスは `.env` の変更を自動では読み直さない。
この方式では自動更新用のリフレッシュトークンを扱わない。

403は権限不足として扱い、トークンの期限切れとは区別する。
