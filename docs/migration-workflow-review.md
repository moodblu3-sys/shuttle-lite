# 移行の入口と仕様レビュー（2026-09-27）

## 実装した入口

「新しい移行」を専用ページにし、先頭に「AIで整理して移行」「そのまま移行」の選択カードを並べる。
既定はAI方式を維持。移行方式→移行名→移行元・移行先→開始前の確認→詳細オプションの順とする。
長い説明文は置かない。設定前に方式を比較でき、開始後は方式を変更しない。

画像は入口の配置案。テストモードや同名処理など既存設定を廃止する意図はない。

## 一般的な移行手順との比較

Microsoft Migration Managerは走査・評価後に移行先と設定を決めて実行し、後から同じタスクで差分移行できる。[1][2]
AWS DataSyncは転送時と転送後の検証、実行サマリーとファイル別レポートを提供する。[3][4]
各製品の具体的な照合・上書き規則は異なる。以下はShuttle Liteの現コードに対する設計判断であり、業界共通規格ではない。

| 論点 | 現状・評価 | 改善案・範囲 |
| --- | --- | --- |
| 方式選択 | 専用ページ先頭のカードで2方式を選択する | AI整理を既定とし、既存の各方式の処理を維持 |
| 開始前の確認 | 開始前にファイル数・容量・読み取りエラーを確認できる | 今回実装。読み取り確認のみで転送しない。エラー・未完了なら開始不可。開始時の再走査で変更があれば再確認 |
| フォルダー構成 | そのまま移行は選択元の最上位フォルダーも作成する | そのまま移行のみ、移行先カード内に「最終配置先：選択したBoxフォルダー / 移行元フォルダー名」を表示。AI方式の重複する範囲表示は削除。構成の選択肢は増やさない |
| 同名処理と差分 | 初回のRENAME/SKIP/OVERWRITEと、追跡済みファイルの差分更新は別。初回RENAMEでも追跡済み更新は同じBox IDの新versionになる | 今回そのまま移行のラベルを「初回の同名ファイル」に変更。処理規則は変更しない |
| テストモード | 実転送して後でテストファイルを削除する。ドライランではない | 事前チェックと区別する。テスト時の上書き禁止は維持し、選択肢を隠さず理由付き無効表示にする案 |
| 差分と切替 | 追加・更新の選択、元で削除したファイルのBox保持、Box側変更の保護は妥当。変更追跡はパス基準 | 改名・移動は新規扱い。最終切替前は元の更新を止め、最終差分・件数と内容の検証後に利用先を切り替える。これは運用手順とし、切替自動化は作らない |
| 権限・所有者 | ファイルサーバーのACL、所有者を対応付けて再現しない | 「そのまま」はフォルダー構成・内容の意味。Boxの配置先の権限設計は別作業。今回マッピングは追加しない |
| 検証と履歴 | 内容ハッシュ検証、再試行、初回・差分のレポートあり | 維持。Snowflakeの処理ログ送信と、実行者・ファイル名を含む監査記録の拡張を区別する |

MVPでは開始前の配置先の見える化と、同名・テストモードの意味の整理を優先する。
ACLマッピング、双方向同期、スケジュール、大量ファイル向け最適化は今回広げない。
現在の差分確認は全走査とハッシュ計算を伴うため、大量ファイルでは確認にも時間がかかる。

## 開始前の確認の範囲

- ファイルを読み取り用に開けるか確認し、メタ情報から件数・容量を集計する。内容の全文読取・ハッシュ検証・Box転送はしない。
- ワーカーと同じ名前除外規則で、隠し項目・Officeロック・Thumbs.db・desktop.iniを除外。リンクはたどらない。
- フォルダー数は選択したルートを除く。エラーがある場合の件数・容量は読み取れた分のみ。
- 走査の上限は10万エントリー（ディレクトリー訪問も含む）、60秒、128階層。超過は未完了として開始しない。
  ネットワーク共有のOS読み取り待ちは強制中断できないため、60秒は厳密なHTTP応答期限ではない。
- 確認結果にはパス・サイズ・時刻・inode等のメタ情報から署名を作り、画面からの開始時に再走査して照合する。
  読み取り不能や差異があればジョブ作成前に拒否する。全走査のスナップショットやソースの排他ロックではない。
- 確認後や転送中の変更を完全に防ぐものではなく、既存のワーカーの変更検出とSHA-1検証も維持する。
- 既存スクリプトとの互換性のため、APIのsourceCheckは省略可能。新しい画面からの開始では必ず送る。
- 今回の確認は新規移行向け。差分移行は既存の差分確認・選択・反映を使う。

## 今回実装した共通導線

- 左メニューは常に「移行一覧」「設定」。移行詳細中も「移行一覧」を選択状態にする。
- 移行内のタブは、AI方式が「進捗／分類・承認／実行履歴」、そのまま方式が「進捗／差分移行／実行履歴」。
- タブは処理状態によらずクリック可能。差分操作は初回実行中には無効。テストモードの差分画面は対象外の理由を表示。
- 既存の進捗・承認URLは維持。差分と履歴に独立したURLを追加する。
