# 開発方針 — 文書の内容に基づく整理と移行

更新日: 2026-09-22

この文書は設計レビューで合意した次の開発範囲を記録する。
以下は実装済み機能の一覧ではない。現行コードとの差分を確認し、関心事ごとに実装する。

## 開発と受け渡し

- ChatGPTを設計・実装・自動テスト・fake Box検証の主担当とする。
- GitHubでコードを受け渡し、社用Macで実Box確認と発表リハーサルを行う。
- 変更は作業ブランチで進め、1つの変更に1つの関心事と対応するテストを含める。
- 検証したコミットを明示する。未実行のテストを成功扱いにしない。
- 公開対象はソース、設定例、合成データの生成処理、テストとドキュメントに限定する。
- 認証情報、実顧客の文書、実環境の設定、状態DB、実行ログは公開しない。
- 開発先は公開リポジトリ [moodblu3-sys/shuttle-lite](https://github.com/moodblu3-sys/shuttle-lite)。
- 2026-09-22に公開状態を確認済み。新しいリポジトリは作成せず、このリポジトリを使う。

## 合意した体験

1. 所属部署が分かっているローカルフォルダを移行対象にする。
2. 文書をBoxのアクセス制限された一時保管先へアップロードし、検証する。
3. 対象部署の既存Boxフォルダから、許可された配置先候補を取り込む。
4. Box AIがファイルの内容と候補を参照し、顧客・案件・文書種類と配置先を提案する。
5. 業務を知る各部署の文書管理担当者が分類先ごとに確認し、まとめて承認する。
6. 承認された文書から順に最終配置する。確認待ちがあっても他の文書は進める。
7. ファイルID、配置先、サイズ、SHA-1、必要なメタデータを検証する。

主な価値は「移行をきっかけに、雑多な文書を整理して使える状態にする」こと。
プロキシ対応は利用環境に合わせた接続機能として扱う。
Box AIには任意のフォルダIDを生成させず、取得・検証済みの候補に対応付ける。
候補があっても案件を一意に特定できない場合は、無理に割り当てない。

## 確認と保留

- 顧客・案件・文書種類を組み合わせた分類にする。
- 案件が特定できない文書は一時保管先に残し、担当者の指定と承認を待つ。
- 案件は分かっても配置先が存在しなければ保留する。
- 不足する配置先は担当者がBoxで用意し、候補を更新する。新規配置先の自動作成は含めない。
- 確認待ちを含むジョブは、全件完了と表示しない。
- 承認する部署は移行元の所属に基づいて決め、AIの分類結果で閲覧先を広げない。
- 文書管理担当者は業務上の役割を表す。複数ユーザーの認証・権限制御が実装済みとは扱わない。

## 承認画面

- 一覧は分類先ごとにまとめ、ファイル名・短い要約・状態を中心に表示する。
- ファイルを選ぶと右側の詳細パネルを開く。
- 詳細には分類理由、判定の根拠となる原文抜粋、元ファイルを開く導線を置く。
- 根拠を取得できない場合は、その旨を表示し、AI生成の説明を原文として扱わない。
- 原文根拠の取得方法と対応条件はBoxの公式仕様と実測で確認してから実装する。
- 個別の修正・保留を行えるようにし、未確定文書を通常の一括承認に含めない。

## 発表での評価

同じ合成文書群と、事前に決めた正解の分類先を用いて、手作業とAI支援を比較する。
手掛かり不足の文書は保留が正解となるよう、評価データに含める。

| 項目 | 記録する内容 |
| --- | --- |
| 人の作業時間 | 準備、確認、修正、承認の時間 |
| 全体の所要時間 | アップロードやAI処理の待ち時間を含む時間 |
| AI提案時の分類品質 | 正解、誤分類、保留の件数 |
| 人の承認・修正後の分類品質 | 正解、誤配置、保留の件数 |

時間短縮や精度の数値は実測前に主張しない。過去の15件の検証結果を、
今回の顧客・案件別分類の精度として流用しない。

## 実装順序

1. 現行MVPのテストとfake Box検証を再現し、開発の基準を記録する。
2. 部署内の顧客・案件・文書種類を表現する配置先候補と、その検証を整える。
3. 既存Boxフォルダから候補を取り込み、更新できるようにする。
4. Box AIによる分類・要約・根拠の取得と、未確定時の保留を整える。
5. 分類先別の一覧と右側の詳細パネルを実装する。
6. 承認済みのみの配置、保留、候補更新を通しで検証する。
7. 合成データで手作業との比較を行い、発表資料とデモに反映する。

各段階を別の変更として検証する。既存機能で満たせる部分は再実装しない。

## Macのフォルダー選択（2026-09-22）

移行元のパス入力を「フォルダーを選択」ボタンに置き換える。
Mac標準の選択画面からフォルダーを選び、名前と場所を確認してから移行を開始する。
選択だけではジョブ作成・転送を行わず、キャンセル時は以前の選択を維持する。

- macOS標準の `osascript` と `choose folder` を使用する。追加依存なし。
- 選択画面はWebを起動したMacに表示する。同じMacのlocalhostから操作する。
- Webの起動をloopbackに限定し、選択APIは同一オリジン・専用ヘッダーを検証する。
- 実行するスクリプトは固定で、ユーザー入力や選択されたパスをコマンドへ埋め込まない。
- 二重起動を防止し、キャンセル・通信中断・タイムアウト時にも次の選択を可能にする。
- Mac以外では未対応を表示する。既存のパス指定APIは維持する。
- D-006・D-017、Box上の配置先候補の設定は変更しない。

仕様は[Apple公式のフォルダー選択ガイド](https://developer.apple.com/library/archive/documentation/LanguagesUtilities/Conceptual/MacAutomationScriptingGuide/PromptforaFileorFolder.html)
と[AppleScriptのchoose folder仕様](https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptLangGuide/reference/ASLR_cmds.html)
を参照した。選択APIのテストではネイティブ処理をモックし、Mac実機でのダイアログ表示・
権限の確認、および選択したフォルダーから実Boxへの移行は社用Macで実施する。

検証: 200テスト、ルートとWebの型チェック、lint、本番ビルドに成功。
本番サーバーへのHTTP確認でパス入力欄の除去、選択ボタン、未対応OSの案内、
選択APIのオリジン・ヘッダー検証を確認した。
ビルドキャッシュの破損による初回エラーは、生成済みキャッシュの削除・再生成で解消した。
既存の動的ファイル追跡に関するビルド警告は継続している。


## 移行ごとの既存Boxフォルダー選択（2026-09-22）

設定画面から配置先候補を削除し、「新しい移行」にBoxのフォルダー選択を追加する。
上記の共通設定に配置先を置く記述を、この節で置き換える。

- フォルダーを開いて選択する。移行先のパス・ID・分類ルールの入力は不要。
- 選択したフォルダー自身と配下の既存フォルダーを取得する。文書本体は閲覧時に取得しない。
- 作成APIで再取得し、移行・開始指示と同じtransactionでSQLiteに保存する。
- 候補は200フォルダー・20階層以内。取得失敗・上限超過では部分的な候補で開始しない。
- 一時保管先・要確認保管先・レポート用フォルダーは選択対象から除外する。
- AIへ候補のkeyだけでなく名前と階層を送る。不明・範囲外の提案は確認待ちにする。
- 承認画面・Worker・最終配置は同じjobの候補を使用する。別jobの配置先は承認できない。
- 配置直前にフォルダーの存在と保存済みの階層・名前を確認し、変化時は確認待ちに戻す。
- 実Boxでは共通サンプルの読み込み・分類先の自動作成・古いcacheの分類先再利用を止める。
  一時保管先などの内部フォルダーは従来どおり作成する。既存Boxオブジェクトは削除しない。
- 既存DBをschema 4へ自動更新する。移行先未選択の過去の実Boxジョブは開始・再開しない。
  ファイルと履歴は保持し、新しい移行で移行先を選び直す。実行中の旧jobも処理前に停止する。
- fake Boxのみ従来のprofile API・合成検証用catalogを維持する。
- 新しい実Box用metadata templateは配置先keyをstringで保持する。
  既存の固定enum templateでは、未対応keyをroutingReasonにpathと共に記録・照合する。
  templateの自動改変は行わない。SQLiteとreportの承認key・最終folder IDは保持する。
- D-006・D-017を維持。新しい依存は追加しない。

公式仕様を確認した箇所:

- [フォルダーのpath_collection](https://developer.box.com/reference/folders-resources)
- [Structured Extractのfields・prompt・options](https://developer.box.com/reference/post-ai-extract-structured/)

引き続き未実装。AIの精度と実Boxの権限による表示・配置はMacで検証する。

検証: 220テスト、ルートの型チェック、lint、Web本番ビルド（型チェックを含む）が成功。
新規作成・別job間の分離・承認後の配置・file ID維持・旧enum template・配置先移動時の停止・

移行作成、jobごとの承認画面/APIを確認した。実ブラウザーのクリック操作・実Boxは未検証。
既存の動的ファイル追跡に関するビルド警告は継続している。
