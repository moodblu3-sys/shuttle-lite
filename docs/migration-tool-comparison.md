# 他の移行ツールと比較した改善候補

調査日：2026-09-23。Box Shuttle、Microsoft Migration Manager、ShareGate Migrateの公式資料を参照。
以下の優先順位はShuttle Liteの卒業発表までの時間と、現在の実装に基づく提案。
他製品の全機能・性能を比較したものではない。

## 今回改善するUI

- 承認一覧はリストを維持し、ファイル名・テンプレート・状態を列で揃える。
- すべて／承認待ち／未選択／要対応を検索と組み合わせ、100件を超える移行全体に適用する。
- 詳細はファイルを選んだときに開き、閉じると一覧を広げる。下書きは保持する。
- 完了後は成功・失敗・除外と結果へのリンクを中心に表示する。
- 全成功・一部失敗・全件除外・対象なしを区別する。ログ送信待ちや失敗も隠さない。

## 次に改善するなら

| 優先度 | 比較から分かること | Shuttle Liteの現状 | 小さく改善する案 |
| --- | --- | --- | --- |
| 高 | Box Shuttleは分析・シミュレーション、Migration Managerは転送前のスキャンと問題の確認を用意する。[1][2] | ファイル走査・転送前検査はあるが、通常フローは開始後に処理が進む。開始前の確認画面はない。 | 移行元を選んだ後に件数・合計容量・読み取り不能などの問題を表示する「事前チェック」。まずローカル検査に限定し、転送やBox AIを実行しない。既存のテストモードは実際に転送するので、この機能とは分ける。 |
| 高 | ShareGateは結果の状態を分け、問題のある行から詳細と対処情報へ進める。[3] | CSV/JSON、エラー種別、失敗分の再実行は既にある。画面上で失敗した全ファイルと原因を追う導線は改善余地がある。 | 完了画面の「失敗 N件」から、対象ファイル・原因・対処を一覧表示する。既存の再実行処理につなぎ、再試行ロジックは増やさない。 |
| 中 | Migration Managerは件数・容量の概要と検索・フィルターを組み合わせる。[2] | 承認対象は今回の改修で絞り込める。移行対象自体を拡張子や更新日で絞る設定はない。 | 実案件で必要になったら、移行前の拡張子・更新日フィルターを追加する。選択範囲と対象件数を必ず一緒に表示する。 |
| 発表後 | Box Shuttleのdelta syncやShareGateのincremental copyは、初回移行後の新規・更新データを扱う。[1][4] | 再スキャンはあるが、移行済みデータの差分更新を扱う完全な同期機能ではない。D-017で同名上書きをしない。 | 必要になった段階で新規追加と更新を分けて設計する。既存ファイルを更新する場合は、D-017との関係、Box側の変更検出、バージョン保護を先に合意する。 |
| 発表後 | Box Shuttleは所有者やユーザー・グループの権限マッピングも扱う。[1] | 現在はファイルの転送・分類・メタデータ付与に焦点を当てる。元システムの権限移行は対象外。 | 卒業発表では対象外を明確にする。権限移行や複数ワーカーの集中管理を今から追加しない。 |

発表前は今回のUI改善を実Boxで確認し、実演中に見つかった問題だけを修正する。
さらに一つ足すなら、操作前に規模と問題を把握できる「事前チェック」を優先する。
新しい分析ダッシュボード、カスタム列設定、スケジュール実行は現段階では優先しない。

## Shuttle Liteとして見せたい点

文書内容に基づく配置先・業務メタデータテンプレートの提案、項目抽出、人による承認を一つの流れで見せる。
比較先に同等の機能が存在しないとは断定しない。大規模移行機能の数を競うより、この用途での操作の少なさと確認のしやすさを重視する。

プロキシ対応は「コードが対応すること」「特定環境で経由を確認したこと」を区別する。
この資料は現在のMacの通信経路を検証した証拠にはならない。デモ当日の起動設定とアクセスログで確認する。
