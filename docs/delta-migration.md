# 差分移行の確認手順

通常の「そのまま移行」だけが対象。AI方式の差分・上書き、削除同期、定期実行は対象外。
初回のBox同名衝突は既定RENAME。OVERWRITEを選ぶと既存IDに新versionを追加する。
前回移行したファイルの更新は同名衝突と別扱いで、差分一覧から選んだものをversion更新する。
元・Boxの両方で変更されたものは強制更新しない。権限・共有設定・業務メタデータを変更しない。

## 合成データによるMac確認（実Boxでは未実施）

1. 専用の移行先と小さな合成ファイル2件を用意し、「そのまま移行」を実行する。
2. 1件の内容を更新し、1件追加する。「差分を確認」で更新1・追加1・変更なし1を確認する。
3. 「差分を移行」を実行し、更新先のBox IDが同じでversionが増え、変更なしのversionが増えていないことを確認する。
4. 再度差分確認し、全件「変更なし」になることを確認する。初回・差分のレポートが残ることを確認する。
5. 元とBoxの両方を編集し「要対応」、Boxだけなら「Box側で変更」になることを確認する。
6. 元から1件削除しても、Boxの内容は残ることを確認する。
7. 分割転送になる合成ファイルでも同じIDの更新・内容検証を確認する。
8. 同名ファイルを用意した初回で「上書き」を選択し、既存IDが維持されることを確認する。
9. 共有フォルダーを使う場合はPC側で接続する。共有を切断した差分確認が失敗し、不完全な一覧を実行できないことを確認する。

## 実装上の制約

- SQLiteの移行履歴が照合の基準。履歴を失うと既存IDへの差分更新を継続できない。
- 元の改名・移動は新規パス。旧ファイルを自動削除しない。
- 確認後の新しいファイルは次の差分確認で拾う。実行途中で対象を追加しない。
- 未確定の転送が残るパスは「要対応」。その実行の再試行でBox側と照合してから差分を確認する。
- 比較は全件ハッシュ。転送量は減るが、大量データの走査性能は未測定。
- マウント先が空のローカルフォルダーとして残るなど、OSが正常読取と判断する切断は検出できない場合がある。
  削除を反映しないためBoxの既存ファイルは消さない。表示が不自然なら再接続して確認し直す。
- 差分一覧に空フォルダー作成も含む。除外チェックはファイル単位で、フォルダーは走査時の構成を作成する。
