# デモ用テストモード

新しい移行で「テストモード」を選択します。通常どおり転送・AI提案・承認・配置を試し、進捗画面の「テストを終了してファイルを削除」を押すと、その回の転送ファイルを一括削除します。完了直後には削除しないため、Box上の結果を確認できます。確認待ちの文書を残した状態でも終了できます。

- 通常の移行と既存の履歴は既定でテストモード無効です。後から通常の移行をテストに変更する機能はありません。
- Macの原本、Boxのフォルダー、移行履歴は残します。次のテストは「新しい移行」から開始します。
- 保存されたファイルID、移行ジョブと文書のメタデータ、SHA-1、バージョン、所在を確認し、etag付きで通常のファイル削除APIを呼びます。フォルダー内の一括削除、ファイル名検索による削除、ゴミ箱の完全削除APIは使いません。
- Boxの企業設定によって通常のファイル削除が完全削除になる場合があります。開始時と削除前に画面で表示します。API仕様: https://developer.box.com/reference/delete-files-id/
- 転送処理の所有権が解放されてから削除します。期限切れだけを理由に稼働中のWorkerから所有権を奪いません。同じMac上でWorkerの終了を確認できた場合は、再起動後に削除処理を引き継ぎます。
- 内容が変更されたファイル、移行のメタデータを確認できないファイル、転送結果のIDが記録されていないファイルは削除せず未解決と表示します。権限不足やAPI失敗も履歴に記録します。「未削除ファイルの削除を再試行」から再実行できます。
- 削除済みIDを記録し、再試行では削除成功分を対象外にします。API成功直後に応答や記録を失った場合は、所在不明を成功とみなさず未解決に残します。
- この操作は移行ファイルが対象です。「レポートをBoxに保存」で別途作成したレポートは残します。AIの利用量や外部ログはリセットしません。

更新後は `npm run db:migrate` を実行します。従来の `npm run demo:reset` は引き続きローカル状態のリセットであり、Boxファイルの後片付けには使用しないでください。
