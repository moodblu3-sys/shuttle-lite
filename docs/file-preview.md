# 承認画面のファイルプレビュー

実Boxモードでは、承認画面の「ファイルの詳細」から「プレビュー」を開けます。
Boxへのアップロードとファイル識別情報の取得が完了したファイルが対象です。

1. リストでファイルを選び、「プレビュー」を押します。
2. モーダル内で内容を確認します。拡大・ページ移動はBox標準ビューアの操作を使います。
3. 右上の「×」で閉じ、一覧で承認します。編集中の値と選択は保持されます。

プレビューの閲覧は必須ではありません。承認、分類、メタデータ付与、テスト終了時の削除は従来どおりです。新しいBoxフォルダや共有リンクの作成も不要です。

## 表示できない場合

- 「再読み込み」で新しいプレビューURLを取得できます。
- 「Boxで原本を開く」から通常のBox画面へ移動できます。この画面の閲覧には利用者自身のBox権限が必要です。
- アップロード直後の変換待ち、非対応形式、Boxの権限・企業設定によって表示できない場合があります。
- テスト終了後のファイルや状態が変わったファイルは、プレビューを発行できません。
- fakeモードでは実Box文書がないためボタンを表示しません。

## 通信と制限

URLの発行は既存のBox認証・プロキシ設定を使うサーバー処理です。文書表示は利用者のブラウザからBoxへ直接通信するため、workerのSquid設定は自動では適用されません。

`expiring_embed_link` を開くたびに取得し、URLをDB・ログ・ブラウザストレージへ保存しません。主アクセストークンはブラウザへ渡しません。返されるURL自体も閲覧権限を持つため、共有しないでください。

iframe内のエラーを外側の画面からすべて検知することはできません。再読み込み・原本を開く・閉じる操作は常に外側に配置しています。iframe内にフォーカスがある場合、Esc操作が外側へ届かないことがあるため、「×」でも閉じられます。

3秒ごとの承認画面更新では同一ファイルのiframeを再読み込みしません。ファイルの差し替えやバージョン変更を検知するとプレビューを閉じます。閲覧はファイルのロックではなく、既存の承認時の整合チェックも引き続き行います。

## 実装と検証

- API: `POST /api/jobs/[jobId]/items/[itemId]/preview`
- 所属job、承認対象状態、cleanup状態、画面・DB・BoxのファイルID/SHA-1/バージョンを検証します。
- プレビュー取得中に状態が変わっていないことも再確認します。
- API/Box通信のテストに加え、DOMテストで開閉、選択・編集保持、定期更新、遅延応答、期限付き再試行を確認します。jsdomは開発時のテスト専用です。
- 実Boxの文書描画、iframe内のページ移動、ブラウザのフォーカス制御、見た目は利用環境での確認が必要です。DOMテストはこれらの代わりにはなりません。
